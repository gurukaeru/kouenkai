# 10万人都市：全体集計の接続

人口モデル・イベント改修は単独HTMLで動きます。全プレイヤーの共有集計には、専用の保存先の公開が必要です。未設定中は画面に準備中と明示し、外部送信しません。

1. 専用の非公開Googleスプレッドシートを作成し、拡張機能→Apps ScriptでCode.gsを配置。
2. setupCityを一度実行。非公開のCityGamesシートを作成します。旧版の1年削除トリガーがあれば停止します。年度比較用にサーバー記録は長期保存し、自動削除しません。

プレイ開始日時（playedAt・UTC形式）とサーバー受信日時を別々に保存します。年度は日本時間の4月1日〜翌年3月31日で、プレイ開始日を基準にします。日時がない旧記録のみ受信日を利用します。集計は同じゲームバージョン内で年度比較し、20ゲーム未満は非表示です。日時は端末申告値のため真正性は保証しません。
3. Webアプリとして「実行者：自分」「アクセス：全員」でデプロイ。スプレッドシート自体を一般公開しないでください。
4. 発行された/exec URLを100k-city.htmlのCITY_STATS_URLへ設定。
5. 年代・性別が未回答でも遊べること、ゲーム終了時に1行保存されること、再送で重複しないこと、20件未満が非表示になることを公開前に検証。チェック式の同意は設けず、開始画面に記録の案内を表示します。noticeVersionは説明の版であり、同意を取得した証跡ではありません。

保存する属性は任意の年代・性別。氏名、住所、メール、支持政党は収集しません。運営目的以外（選挙勧誘、広告配信、個人の政治思想推定）へ転用しない運用とします。保存先サービス側の通信ログは別途そのサービスの管理対象です。

公開画面は予算配分の平均比率とイベントごとの選択比率です。希望案・実行案・議会修正・イベント選択の原データは公開しません。イベントの善悪と政治思想を結びつけたスコアは作りません。イベント別では各ゲーム最初の回答のみを数え、選択肢に1〜19件の少数回答がある場合はそのイベント全体を非表示にします。

1ゲーム単位の統計であり、ユニーク人数や世論調査ではありません。同一ゲームIDの再送は重複保存しませんが、プレイヤーのやり直しは別ゲームです。クライアント由来のデータなので真正性は保証できず、本格運用にはレート制限・不正投稿対策が必要です。

公開前にプライバシーポリシーへ本機能の保存目的、保存先、任意回答の属性、保持期間、問い合わせ窓口を追記してください。後から既存端末記録を自動一括送信しない設計です。チェックボックスの撤去は、法的に同意が不要であることを判断したものではありません。
